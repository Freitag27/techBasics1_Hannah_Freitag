# Trembling Tunnels

## Description

Trembling Tunnels is a point-and click story game, which is my final for Tech Basics 1. It uses Python and Pygame.
In the game, you explore a cave, trying to uncover its secrets. There are six different endings. Your progress should automatically be saved to the device, so you can pause and come back later to try different choices after completing each run

## Requirements: 

Python 3.8 or newer
Pygame 2.0

## How to play

Download the repository from GitHub (this one or: https://github.com/Freitag27/trembling-tunnels.git - I made an extra repository for just the game, you you don't need to download all of my projects in this repository.)
Run it with python or terminal (make sure python is downloaded to your terminal)
 'main.py' is the file that starts the game !

The following files mus be present in order for the game to work: 
achievements.py
main.py
mainmenu.py
scoresaving.py
tremblingtunnels.py
assets folder with 'backgrounds', 'items' and 'other subfolder' + its contents

trembling_tunnels_stats.txt: is created automatically on first run,
                             stores your achievement history.
                             Delete this file to reset all achievements.
## How to play: 

Controls: Space Bar or enter - advance dialogue, finish typing
double-clicking an item: pick it up
double-clicking an item in inventory: using it

## Good to know: 

there is no process saving or pause button mid-run. The game should take (15 min max) to complete

## Sources: 

All pictures/sounds were downloaded on pixabay.com, and changed in procreate.

## Thoughts & learnings 

### What I did: 
The idea for the story came from our assigment of text-based inventory games. I had lots of fun making it up, so I wanted to update it with music, visuals, rework some of the dialogue etc. for my final project.
Then, for my presentation, I made the main menu to show. Then at home I found pictures of every Item I wanted to have on pixabay, because there the pictures are not copyrighted and 
one is allowed to use them without giving credits. Some pictures, I had to adapt to fit my liking/imagination, for example the background for the meadow in the beginning.
I also tried to make the mood scarier by editing the pictures to be very dark and desaturated. After I had all of my pictures assembled, I started coding. I made sure to
start with the intro and only add new parts slowly, so I could check that everything ran smoothly in between. Honestly, it was frustrating at times, because I'm less the type to 
explain things in great detail and just hope that people 'catch my vibe'. However, obviously python doesn't work like that and one needs to be precise as well as thorough when coding.

In terms of learnings I was very inspired at the way that bugs and problems are handled during the course. 
Instead of becoming frustrated, I often witnessed a 'huh, interesting...'-attitude when I asked for help, which made problems seem like less of a deal.
Trying to approach bugs the same way when coding my own game really helped me.

I have to admit, that I forgot to commit changes until I revisited the tech basics mystudy. I also didn't get around to putting in more items (which was originally my plan)
,as getting the game to work was already time-consuming. 
Nevertheless, it's amazing to me that I've basically made a game now, even if it is very simple.
I could not have imagined doing this half a year ago. I hope it works and playing it is fun :)
